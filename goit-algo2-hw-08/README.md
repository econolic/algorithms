# Тема 7-8. Алгоритми оптимізації та керування ресурсами

## Завдання 1. Оптимізація доступу до даних за допомогою LRU-кешу

`task_1.py` реалізує LRU-кеш для оптимізації доступу до даних. Кеш обмежений за розміром і автоматично видаляє найстаріші елементи при досягненні ліміту.


### Особливості реалізації

- `range_sum_no_cache` рахує суму діапазону напряму через зріз масиву;
- `update_no_cache` оновлює значення без додаткових структур;
- `range_sum_with_cache` використовує LRU-кеш ємністю `1000` для повторних запитів `Range(left, right)`;
- `update_with_cache` оновлює масив і лінійно видаляє з кешу всі діапазони, що містять змінений індекс;
- benchmark використовує `n = 100_000`, `q = 50_000` і фіксований `random.seed(42)`;
- для перевірки коректності рахується checksum усіх результатів `Range` і порівнюється між запуском без кешу та з кешем.

### Складність

- `range_sum_no_cache` і cache-miss у `range_sum_with_cache` працюють за `O(r - l + 1)`;
- cache-hit у `range_sum_with_cache` працює за `O(1)`;
- `update_no_cache` працює за `O(1)`;
- `update_with_cache` працює за `O(k)`, де `k` - кількість записів у кеші, бо інвалідація виконується лінійним проходом по ключах;
- пам'ять LRU-кешу обмежена `O(k)`, де `k <= 1000`.

### Запуск

```bash
python goit-algo2-hw-08/task_1.py
```


## Завдання 2. Реалізація Rate Limiter з використанням алгоритму Sliding Window для обмеження частоти повідомлень у чаті

`task_2.py` реалізує Rate Limiter, який обмежує кількість повідомлень, що користувач може надіслати в чаті за певний проміжок часу, використовуючи алгоритм Sliding Window.

### Особливості реалізації

- `SlidingWindowRateLimiter` зберігає історію повідомлень кожного користувача у `collections.deque`;
- `_cleanup_window` видаляє timestamp-и, що вийшли за межі активного вікна, і прибирає користувача зі словника, якщо його історія стала порожньою;
- `can_send_message` перевіряє, чи не перевищено ліміт у поточному 10-секундному вікні;
- `record_message` записує повідомлення тільки тоді, коли воно дозволене;
- `time_until_next_allowed` повертає час очікування в секундах або `0.0`, якщо користувач може писати зараз.

### Складність

- очищення вікна амортизовано працює за `O(m)`, де `m` - кількість застарілих записів, які видаляються під час конкретного виклику;
- `can_send_message`, `record_message` і `time_until_next_allowed` після очищення працюють за `O(1)`;
- пам'ять становить `O(u * r)`, де `u` - кількість активних користувачів, а `r` - кількість timestamp-ів у вікні для одного користувача.

### Запуск

```bash
python goit-algo2-hw-08/task_2.py
```
