# Тема 5. Алгоритми роботи з великими даними

## Завдання 1. Перевірка унікальності паролів

`task_1.py` реалізує фільтр Блума для перевірки, чи пароль уже
зустрічався раніше. Паролі не зберігаються у фільтрі напряму: структура
тримає лише біти, виставлені кількома хеш-функціями.

### Особливості реалізації

- `BloomFilter` використовує `bytearray`, тому споживання пам'яті залежить
  від розміру фільтра, а не від кількості доданих паролів;
- `add` додає рядок до фільтра;
- `contains` і оператор `in` перевіряють наявність рядка;
- `check_password_uniqueness` повертає статус для кожного нового значення:
  `вже використаний`, `унікальний` або `некоректний`;
- порожні рядки та значення не рядкового типу не додаються і позначаються як
  некоректні.

### Складність

- `add` працює за `O(k)`, де `k` - кількість хеш-функцій;
- `contains` також працює за `O(k)`;
- `check_password_uniqueness` для `n` паролів працює за `O(n * k)`;
- пам'ять фільтра становить `O(m)`, де `m` - розмір бітового масиву, і не
  залежить від кількості доданих паролів;
- фільтр Блума може давати хибнопозитивні спрацювання, але не дає
  хибнонегативних для коректно доданих значень.

### Запуск

```bash
python goit-algo2-hw-06/task_1.py
```

### Результат виконання

```text

Пароль 'newpassword' - унікальний.
Пароль 'admin123' - вже використаний.
Пароль 'guest' - унікальний.
```

## Завдання 2. Порівняння точного підрахунку та HyperLogLog

`task_2.py` потоково читає `logs/lms-stage-access.log`, дістає
IP-адреси з поля `remote_addr`, ігнорує некоректні рядки та порівнює два
підходи до підрахунку унікальних адрес.

### Особливості реалізації

- точний метод використовує `set`;
- наближений метод використовує власну реалізацію HyperLogLog на 64-бітних
  хешах із `precision=14`;
- для малих наборів застосовується small-range correction;
- результати містять кількість унікальних елементів і час виконання для
  кожного методу;
- сторонні залежності не потрібні.

### Складність

- завантаження IP-адрес виконується потоково за `O(n)` часу, де `n` -
  кількість рядків у лог-файлі;
- точний підрахунок через `set` працює за `O(n)` часу та потребує `O(u)`
  пам'яті, де `u` - кількість унікальних IP-адрес;
- HyperLogLog працює за `O(n)` часу та потребує `O(2^p)` пам'яті, де `p` -
  precision, у реалізації використано `p=14`;
- на відміну від `set`, пам'ять HyperLogLog не зростає разом із кількістю
  унікальних IP-адрес;
- HyperLogLog повертає наближений результат, тому можливе невелике
  відхилення від точного підрахунку.

### Запуск

```bash
python goit-algo2-hw-06/task_2.py
```

### Результат виконання

```text

                           Точний підрахунок    HyperLogLog
Унікальні елементи                      28.0           28.0
Час виконання (сек.)                1.716502       1.190612
```
